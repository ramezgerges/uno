# Implementation Plan: X11 IME Support for TextBox

**Branch**: `002-x11-ime-support` | **Date**: 2026-03-16 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-x11-ime-support/spec.md`

## Summary

Add IME (Input Method Editor) support to the X11 Skia target by implementing `IImeTextBoxExtension` for X11 using the XIM protocol. The existing managed TextBox composition logic (text insertion, underline rendering, TextComposition events) is already complete from the Win32 implementation. This plan covers only the X11 platform bridge: enabling XIM, creating XIC per window, intercepting IME events, and routing them through the existing interface.

## Implementation Approach

### Phase 1: X11 P/Invoke Bindings

Add the missing XIM/XIC function bindings to `x11bindings_XLib.cs`:
- `XOpenIM`, `XCloseIM` — open/close input method
- `XCreateIC`, `XDestroyIC` — create/destroy input context per window
- `XSetICFocus`, `XUnsetICFocus` — manage IC focus
- `XmbLookupString` (or `Xutf8LookupString`) — composition-aware text lookup
- `XFilterEvent` — IME event filtering
- `XSetICValues` — set preedit spot location
- Required constants: `XIMPreeditCallbacks`, `XIMStatusNothing`, `XNInputStyle`, `XNClientWindow`, `XNFocusWindow`, `XNSpotLocation`, etc.
- Required structs: `XPoint` (for spot location)

### Phase 2: Enable IME in X11ApplicationHost

- Change `XSetLocaleModifiers("@im=none")` to `XSetLocaleModifiers("")` to enable system default IME
- Register `IImeTextBoxExtension` via `ApiExtensibility.Register`

### Phase 3: X11ImeTextBoxExtension Implementation

Create `X11ImeTextBoxExtension.cs` implementing `IImeTextBoxExtension`:
- Singleton pattern (like Win32)
- `StartImeSession(TextBox)`: Get the X11 display/window from the TextBox's XamlRoot, create XIC if not exists, call `XSetICFocus`
- `EndImeSession()`: Call `XUnsetICFocus`, reset composition state
- Track composition state (`_isComposing`)
- Raise `CompositionStarted`, `CompositionUpdated`, `CompositionCompleted`, `CompositionEnded` events

### Phase 4: Event Loop Integration

- In `X11XamlRootHost.x11events.cs`, call `XFilterEvent` before the event dispatch switch. If it returns true, skip the event.
- In `X11KeyboardInputSource.ProcessKeyboardEvent`:
  - Replace `XLookupString` with `XmbLookupString` using the window's XIC
  - Handle lookup status: `XLookupChars` (committed text), `XLookupKeySym` (key only), `XLookupBoth`, `XLookupNone`
  - During composition, the IME extension handles text — normal key processing is suppressed by the managed TextBox layer's `_isComposing` guard

### Phase 5: Candidate Window Positioning

- When the managed layer updates caret position, call `XSetICValues` with `XNSpotLocation` to position the candidate window
- This is analogous to `ImmSetCandidateWindow` on Win32

## Key Design Decisions

1. **Reuse existing interface unchanged**: `IImeTextBoxExtension` and all managed TextBox composition logic (state tracking, text replacement, underline rendering, TextComposition events) from the Win32 implementation work as-is.

2. **XFilterEvent at event loop level**: Must be called for every X11 event, not just key events. This is how XIM intercepts events for composition processing.

3. **XIC lifecycle tied to window**: Each X11 window gets one XIC. The extension tracks which window is active via the TextBox's XamlRoot.

4. **Thread safety**: X11 calls must use the existing `X11Helper.XLock` pattern. XIM callbacks may arrive on the event thread and must be marshalled to the UI thread via `QueueAction`.

## Complexity Tracking

No constitution violations. The implementation follows existing patterns (singleton extension, ApiExtensibility registration, P/Invoke bindings in x11bindings files).
